# PRD — 归处 Guichu（电子族谱）

> 这是项目的"合同"。任何功能是否"完成"，以本文件为准。

## 1. 一句话定义

**归处** 是一款本地优先、开源的电子族谱 App。它帮你在一部手机里完成三件事：
1. **一键记住祖先坟墓的 GPS 位置，并能一键导航回去。**
2. **把长辈的记忆、口头禅、价值观、人生故事蒸馏成一份可对话的"数字人格"（.skill 文件）。**
3. **（可选）克隆长辈的声音，让你在他/她离开后仍然可以"听到"回应。**

## 2. 为谁做（Target Users）

- **主目标**：30–55 岁的在外子女/孙辈。父母健在时想记录，父母离世后想纪念与追思。
- **次目标**：族谱整理者、家史写作者、民俗/人类学研究者。
- **非目标用户**：需要商业化云服务的企业、需要多人协作实时同步的团队。

## 3. 核心价值主张

> "在你还来得及的时候，把他们留下来。"

归处不是社交产品，不做点赞、不做关注、不做任何上传到公共服务器的动作。**它是一个本地的、私人的、传家的数字档案。**

## 4. 功能清单（In Scope）

### F1 — 祖先坟墓定位（Grave Pin）
**目标**：让用户在扫墓现场用 3 秒完成位置记录。

用户故事：
- 作为在外子女，我清明回老家扫墓时，站在祖父坟前按一下"记录位置"，App 自动保存当前 GPS 坐标 + 我拍的一张照片 + 语音备注。
- 作为一个没用过 App 的中年人，我不想填表单，只想按一个大按钮。

验收标准：
- [ ] 主页有一个显眼的圆形大按钮，文字"📍 记录此地"
- [ ] 按下后 ≤3 秒完成定位（GPS 精度 ≤10 米时自动确认；超时提示手动确认）
- [ ] 自动填入时间戳，用户只需选一个"关联的长辈"（可跳过）
- [ ] 支持附加多张照片（现场拍或从相册选）和一段 ≤60 秒的语音
- [ ] 所有数据落地在手机本地 SQLite，**不上传任何服务器**
- [ ] 离线可用（没信号也能记录，回到有信号时不需要"同步"任何东西）

### F2 — 寻路指南 + 导航（Route Guide & Navigate）
**目标**：让用户不仅记住终点坐标，还能记录一条完整的"图文寻路指南"——从村口/下车点到坟墓的每一个关键路口和标志物，下次回来一步步跟着走。

用户故事：
- 作为每年清明才回一次的人，我从村口开始，沿路走向祖父的坟，每经过一个岔路口或标志物（大柳树、红砖房、水塘），按一下"📌 记录路线点"，拍一张照，写一句备注（如"这里右转"）。到了坟前按"到了"结束。
- 下次回来，我打开祖父的"寻路指南"，看到一条由 5 个路线点组成的图文路线，照着一步步走就到了——比 GPS 导航在山间小路上靠谱 100 倍。
- 我也可以直接一键调起第三方地图导航到终点坐标（粗略定位到附近）。

验收标准：
- [ ] **记录路线模式**：用户开启后，底部常驻浮动按钮"📌 记录路线点"
- [ ] 每个路线点自动记录 GPS 坐标 + 时间，用户可附加：
  - 一张照片（必选，拍路口/标志物）
  - 一句文字备注（如"左转上坡"、"过桥后直走"，≤50 字）
  - 一段 ≤30 秒语音备注（可选）
- [ ] 路线点按记录顺序串联，**自动编号**（① → ② → ③ → … → 终点 📍）
- [ ] **最后一个路线点自动关联墓地坐标**（即 F1 的定位点）
- [ ] 路线记录完毕后可预览：**竖向图文列表**，每个点一张大图 + 备注 + 小地图
- [ ] 路线点可编辑（改图片/改备注）、可删除、可在中间插入新点
- [ ] **寻路模式**：下次回来，打开寻路指南，从第一个路线点开始，依次显示图片和备注，用户点"下一步"切到下一个点
- [ ] 一键调起第三方地图 App 导航到终点坐标（iOS → Apple Maps / Android → 系统默认，可在设置切换高德/百度/Google Maps）
- [ ] 不自建地图引擎（节省 App 体积，不依赖付费 key）
- [ ] 支持上传**相册已有照片**（不只是现场拍，事后整理也可以添加）

### F3 — 蒸馏长辈 .skill
**目标**：把长辈的记忆、口头禅、人生经历、价值观转化成一份可复用的 Markdown Skill 文件，参考 Anthropic 官方 Skills 规范。

用户故事：
- 作为孙子，我坐在奶奶对面，用 App 的"引导式访谈"功能，按提示问她 20 个问题（童年、爱情、遗憾、给后辈的话……），每个问题 App 自动录音+转文字。
- 访谈结束后，App 把这些素材交给 LLM，生成一份 `奶奶.skill` 文件，里面包含：人格描述、说话风格、典型句式、核心回忆、价值观、禁忌话题。
- 我可以随时编辑这份文件（它就是一份 Markdown，像笔记一样可读）。

验收标准：
- [ ] 内置**引导式访谈模板**，5 大主题 × 20 个默认问题，用户可自定义增删
- [ ] 每个问题支持录音（本地存储）+ 自动转写（调用用户自配的 ASR API，可跳过）
- [ ] 访谈完成后，调用 LLM 生成 `.skill` 文件，**结构对齐 Anthropic Skills 规范**：
  ```
  ---
  name: 奶奶-李秀兰
  description: 1938 年生于山东潍坊，小学文化，一辈子务农，说话带山东腔……
  ---
  # 身份
  ...
  # 说话风格
  ...
  # 核心记忆
  ...
  # 价值观
  ...
  # 禁忌
  （不提起 xxx 事；生前不愿被问起 yyy）
  ```
- [ ] 生成的 `.skill` 文件可导出到相册/文件/邮件/其它 App，用户拥有完整所有权
- [ ] **支持反向导入**：把别人做好的 `.skill` 文件导入归处

### F4 — 与长辈对话（Talk to Ancestor）
**目标**：基于 `.skill` 文件与长辈数字人格进行文字/语音对话。

用户故事：
- 作为思念奶奶的人，我打开奶奶的详情页，点"和奶奶聊聊"，输入"奶奶，我最近工作压力很大"，奶奶以她一贯的山东腔回答我。
- 如果我做了声音克隆，回答以她的声音念出来。

验收标准：
- [ ] 对话底层接口为 **OpenAI 兼容格式**（用户可在设置里填 DeepSeek / Kimi / Claude / OpenAI / 本地 Ollama 的 baseURL + apiKey）
- [ ] 默认推荐 **DeepSeek**（中文自然、便宜、响应快）
- [ ] 系统 prompt 自动拼接 `.skill` 文件内容作为人格载体
- [ ] 上下文长度 ≥ 20 轮对话
- [ ] 对话历史本地保存，可清空、可导出 Markdown
- [ ] **伦理护栏**：首次进入对话页时强制弹窗 —— "这是一个基于你记录的内容生成的数字人格，不是真人。它无法回答你未曾记录的事情。"

### F5 — 声音克隆（Voice Clone，可选）
**目标**：让长辈的回答用他/她自己的声音念出来。

用户故事：
- 作为技术型用户，我在访谈时录了至少 30 秒清晰的长辈说话样本，App 提示我可选生成"声音档案"。
- 生成后，对话页多出一个"🔊 用奶奶的声音念"开关。

验收标准：
- [ ] 采用**适配器模式 + BYOK**，内置三个实现：
  - `system-tts`（零配置默认，用系统 TTS，不克隆，适合所有人立即可用）
  - `minimax-api`（调用 MiniMax 语音克隆 API，用户自填 key）
  - `elevenlabs-api`（调用 ElevenLabs API，用户自填 key）
- [ ] 用户在"设置 → 语音引擎"切换实现
- [ ] 克隆生成的"声音档案"保存在本地，与 `.skill` 文件绑定
- [ ] **伦理护栏**：生成前要求用户勾选确认框"我已获得本人或直系亲属授权使用此声音"

### F6 — 族谱树（Family Tree View）
**目标**：简单的可视化家谱，把人和人连起来。

用户故事：
- 我打开"族谱树"页面，看到一个从上到下的树状图，根节点是我的曾祖父，末端是我。
- 点任何一个节点可以跳转到那个人的详情页（包含 .skill、墓地定位、声音档案、访谈录音）。

验收标准：
- [ ] 支持最多 5 代人、单家族（复杂族谱留到 v2）
- [ ] 节点可拖动、可添加父母/配偶/子女
- [ ] 数据结构与后端 schema 一致（见 BACKEND_STRUCTURE.md）

### F7 — 习俗指南（Custom Rituals Guide）
**目标**：根据长辈的去世日期 + 用户所在地区的风俗，自动提醒上坟该带什么、家里该怎么做。让年轻人不再"不知道该做什么"。

用户故事：
- 作为在外地工作的 90 后，爷爷去世了。我不知道头七要做什么、百日要做什么、第一年春节对联贴什么颜色。我在 App 里填了爷爷去世的日期和"山东潍坊"，App 自动告诉我接下来每个重要日子该做什么。
- 今年是爷爷去世第三年（"三周年"），App 提前 7 天提醒我"三周年祭"快到了，并告诉我按照山东潍坊的习俗需要准备什么祭品。
- 清明节前，App 告诉我"清明上坟建议准备：纸钱、香烛、供果、酒，潍坊习俗还会带饺子"。

验收标准：
- [ ] `ancestors` 表新增 `death_date`（精确到日，可空，比原来的 `death_year` 更精确，两者共存兼容）
- [ ] **设置页新增「我的地区」**，支持省 → 市两级选择（如"山东省 → 潍坊市"）
- [ ] App 内置**习俗知识库**（JSON 格式，打包在 App 里，不联网）：
  - 通用习俗（全国共有：头七、百日、周年、三周年、清明、中元、寒衣节、除夕……）
  - 地区特色习俗（按省市分类，各地差异部分）
- [ ] 自动计算长辈去世后的所有重要日期：
  - 头七（去世后第 7 天）
  - 三七 / 五七 / 七七（21 / 35 / 49 天）
  - 百日（100 天）
  - 周年祭（1 年）
  - 三周年祭（3 年）
  - 每年的清明 / 中元节(七月半) / 寒衣节(十月初一) / 除夕
- [ ] **长辈详情页新增「习俗日历」卡片**：
  - 显示下一个即将到来的重要日子 + 倒计时
  - 展开可看全部日历时间线
- [ ] 每个重要日子点进去显示：
  - 📅 日期（农历 + 公历）
  - 📋 该做什么（如"烧纸、上香、供果"）
  - 🛒 要带什么（清单形式，可勾选）
  - 📖 相关习俗说明（如"三周年祭是最后一次大祭，之后转为常规清明祭扫"）
  - 🏠 家里要注意什么（如"去世第一年春节贴**白色或蓝色**对联，不贴红色；第二年贴**绿色**；第三年恢复红色"）
- [ ] **本地通知提醒**（可选）：重要日子前 7 天 / 前 1 天发送本地推送
- [ ] 习俗知识库**开源可贡献**：任何人可以通过 PR 添加自己家乡的习俗
- [ ] 暂不支持的地区显示通用习俗 + 提示"欢迎贡献你的家乡习俗"

## 5. 明确非范围（Out of Scope）

以下功能**不做**，即使用户要求：

- ❌ 云端同步 / 多设备共享 / 账号系统（本地优先，彻底无服务端）
- ❌ 社交功能（评论、点赞、关注、分享到动态）
- ❌ 在线付费购买皮肤/模板/AI 额度
- ❌ 收集任何用户数据上报到我方服务器（我方**没有**服务器）
- ❌ 内置任何 API key 或预付费额度
- ❌ 商业化纪念馆/墓地广告
- ❌ AR 扫墓特效（v2 考虑）
- ❌ Web 端（只做移动端，见 TECH_STACK.md）

## 6. 成功标准（Success Metrics）

这是开源项目，我们不追踪用户行为。成功的衡量是：

- [ ] **可安装性**：任何人 clone 仓库后，按 README 步骤 15 分钟内能在自己的手机上跑起来
- [ ] **核心路径可用**：新用户 60 秒内完成第一次"记录坟墓位置"
- [ ] **社区反馈**：GitHub issue 中至少有 3 位用户反馈"帮我记录了外婆的故事"
- [ ] **代码质量**：核心模块单元测试覆盖率 ≥ 60%
- [ ] **文档完整**：任何贡献者读完 `docs/` 目录能独立添加新功能

## 7. 伦理与边界声明

归处涉及死亡、记忆、声音克隆，必须设护栏：

1. **这不是"复活"**：所有对话页都强提示"基于记录内容生成，非真人"
2. **声音授权**：克隆声音前强制用户确认获得授权
3. **遗嘱机制（v2）**：长辈可指定"我走后这份 .skill 归谁"
4. **删除权**：一键销毁某位长辈的全部数据（包括访谈录音、.skill、声音档案）
5. **不触及宗教**：App 不做祭拜仪式、不烧电子纸钱、不念经 —— 只做"记录与对话"
6. **未成年人保护**：对话模型输出由用户自己选的 API 提供，我们在默认 system prompt 中加入"避免谈论死亡恐吓、宗教煽动、财产纠纷"
